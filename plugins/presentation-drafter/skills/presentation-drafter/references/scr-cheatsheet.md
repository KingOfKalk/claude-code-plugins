# SCR Framework — Quick Reference

> Originated by Barbara Minto (McKinsey, 1960s). Published in _The Pyramid Principle_ (1985).

## The Three Elements

| Element          | Purpose                          | Key question                                     | Share of content |
| ---------------- | -------------------------------- | ------------------------------------------------ | ---------------- |
| **Situation**    | Shared, noncontroversial context | _What does everyone already agree on?_           | 10–15%           |
| **Complication** | Tension, change, or threat       | _Why can't we just keep doing what we're doing?_ | 15–20%           |
| **Resolution**   | Answer, action, recommendation   | _So what do we do about it?_                     | 60–70%           |

**Connectors:** S _…but…_ C _…therefore…_ R

## Order Variants

| Variant                | Order         | Use when                                                   |
| ---------------------- | ------------- | ---------------------------------------------------------- |
| **SCR** (standard)     | S → C → R     | Audience is skeptical; build the case first                |
| **RSC** (answer-first) | R → S → C     | Audience is receptive; lead with recommendation            |
| **CSR** (concerned)    | C → S → R     | Audience already feels the pain; validate first            |
| **SCQA** (full Minto)  | S → C → Q → A | Complex problems; explicit Question helps frame hypotheses |

## Building a Slide Deck with SCR

1. **Write the storyline first** — text only, no PowerPoint
2. **Dot-Dash method** — each "dot" = action title (full sentence), each "dash" = supporting data
3. **Horizontal logic** — slide titles alone tell the complete story
4. **Vertical logic** — each slide's title is proven by its body content
5. **Executive summary slide** — bold claims + indented evidence; Resolution dominates

## SCR by Context

| Context               | Tip                                                              |
| --------------------- | ---------------------------------------------------------------- |
| **Executive / Board** | Lead with answer (RSC). Frame S around what they measure.        |
| **Project Kickoff**   | Use SCQA to co-create hypotheses.                                |
| **Sales Pitch**       | S = buyer's world. C = their pain. R = your product. ≤15 slides. |
| **Email / Memo**      | Three paragraphs max. One S, one C, rest is R.                   |
| **Strategy Deck**     | Heavy C section (market data, competition), then deep R.         |
| **Change Mgmt**       | Use CSR — validate anxiety first, then offer path forward.       |

## Top Mistakes

| Mistake                        | Fix                                                    |
| ------------------------------ | ------------------------------------------------------ |
| Situation too long             | Max 1–3 slides. Audience wants solutions.              |
| Debatable facts in Situation   | Only include what the room already accepts.            |
| Weak Complication (no urgency) | Add data: numbers, deadlines, consequences.            |
| Vague Resolution               | Specify what, how, who, when.                          |
| Data dump without narrative    | Show minimum data needed per claim.                    |
| Force-fitting SCR everywhere   | Skip for info updates, brainstorms, inspiration talks. |

## One-Liner Template

> **[Subject]** is currently **[Situation]**. However, **[Complication]**. Therefore, we recommend **[Resolution]**.

## Multiple Complications Variant (S + C + C + C + R)

One situation, three escalating complications each backed by data, one resolution. Creates compounding urgency via rule of three.
